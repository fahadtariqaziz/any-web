# Small change or bigger change?

Use when the user wants something new and asks how to get it, or is unsure which mode to use.

- "Request some change in app" (small): one coding-agent task inside the approved brief: adjust behaviour, layout or
  wording, fix a bug, add a small feature that the brief already allows. It does not change the brief or the plan.
  Cost: one task attempt (see the Cost card; earlier changes in <cost> show typical amounts).
- "Plan a bigger change" (bigger): a new capability, a new screen or mode, anything the brief lists as out of scope,
  or several related features. The brief is updated first (the user approves it), then the planner adds ONLY the new
  tasks on top of what is built (the user approves that plan), then only those tasks run. Built work and earlier
  changes are kept. Costs more: a brief revision, a plan and several tasks.
- Check the brief's out-of-scope list and the MVP before answering; quote the line that decides it.
- Mention the project limits from <cost> when the coding-agent budget is getting low.
